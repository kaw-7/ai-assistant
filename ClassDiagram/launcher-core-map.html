Notes

What the boxes and arrows can't show

  1. 01

    The original config files are never rewritten. The launcher stores only the differences the user typed and re-applies them at start-up, so config.py stays the readable default. write_back on a dotenv source is the single opt-in exception.

  2. 02

    Overrides are keyed by config-source id, not by module id. Two modules returning a source with the same id genuinely share the values — the same way they share config.py today.

  3. 03

    Discovery never raises. A module that fails to import, has no id, duplicates one, or blows up in its constructor is collected into ModuleRegistry.errors and shown in the UI; the other modules still load.

  4. 04

    Only classes defined in the scanned file count. _collect() checks obj.__module__ == py_module.__name__, so a RunnableModule merely imported into a module file is ignored — and files starting with _ are skipped entirely, which is what makes modules/_sources.py a plain helper.

  5. 05

    Previews are deliberately side-effect-free. The project's config files create their output folders while being read, so evaluate(side_effects=False) patches Path.mkdir and os.makedirs to no-ops while the user is still typing.

  6. 06

    Declared fields are refined, not replaced. A spec in field_specs inherits its default, its help text from the trailing # comment, and its derived flag from the parsed file; anything the file declares but the spec omits still appears under "Other settings" as a plain text box.

  7. 07

    Worth knowing: persist=False fields (passwords) stay out of launcher_settings.json, but as_dict() merges them into the temporary overrides JSON handed to the child. That file sits in %TEMP% in plaintext until the run ends.

  8. 08

    Two silent fallbacks. If a config file cannot be executed in isolation, PyModuleConfigSource falls back to a plain import plus flat overrides (derived values then stay stale), and SettingsStore.load() swallows a corrupt settings file by starting empty. Both are quiet by design; neither reports to the UI.
